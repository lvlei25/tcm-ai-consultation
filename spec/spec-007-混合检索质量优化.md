# spec-007：混合检索质量优化

对应基线：spec-001-中医AI问诊平台搭建.md、spec-003、spec-004

## 变更原因

当前 `kb/retriever.py` 有三处影响 top 6 命中质量的因素：

1. `jieba` 未加载中医词典，"舌质淡红""脉细数"等术语被切碎，BM25 路召回受损
2. 融合权重固定 0.6/0.4、候选固定 20，无去冗余机制，同书相邻块易重复进入 top 6
3. 分块固定 500/80，未按标题层级自适应，长条文被切断、短条文被稀释

## 设计依据

- 中医术语是关键词检索的最小语义单位，需通过自定义词典保证不被误切
- 相邻块内容高度重叠，需在融合后做冗余抑制，提升证据多样性
- 参数集中到 config.py，便于按实测结果调优，不散落在代码中

## 变更内容

| 文件 | 变更 |
|------|------|
| config.py | 新增 `MEDICAL_DICT_FILE`（data/medical_dict.txt，可选）、`MMR_LAMBDA`（默认 0.7）、`BM25_WEIGHT`（由 `1 - VECTOR_WEIGHT` 显式化） |
| data/medical_dict.txt | 新增中医术语词典（舌象、脉象、证型、方剂等，每行 `词 词频 词性`） |
| kb/loader.py | 词典存在时启动时 `jieba.load_userdict`，构建与检索两侧共用 |
| kb/retriever.py | 新增 `_mmr_select()`：融合排序后按 MMR 抑制冗余（`MMR_LAMBDA` 权衡相关性与多样性），再取 `top_k` |
| kb/retriever.py | 检索语句与块文本统一走分词入口，保证构建侧与查询侧词典一致 |
| kb/loader.py | 分块参数支持按标题层级自适应（一级/二级标题下优先按段切分，段落超长再走长度切分） |

## 验证

- `python -m pytest tests/ -q` 全量通过，新增用例见 spec-008
- 以 spec-005 记录的样例问诊单为基线，对比优化前后 top 6：
  - 命中证据是否覆盖主症相关医案
  - 重复出处（同一文件相邻块）条数是否下降
  - 融合分分布是否合理
- 浏览器实测检索明细表，两路得分与融合分仍符合 0.6/0.4 加权

## 注意事项

- MMR 仅在融合排序后作用，不改变 `score` 计算逻辑，spec-003 的明细断言不受影响
- 词典文件为纯文本，不含任何 Key 或敏感信息，可入库
- 参数调整以实测为准，结论回写本 spec「验证结果」

## 修订

- 2026-10-17：新增 `kb/builder.py: rebuild_bm25()` —— 词典变化后只需按 chunks.json 重建
  BM25，不重新向量化；新增统一分词入口 `kb/loader.py: tokenize()`，构建侧与检索侧共用
- 2026-10-17：分块按标题层级自适应**暂缓** —— 改动会使现有向量缓存全部失效并触发全量重新
  向量化，收益需配套评估集验证；待下次语料调整时与全量重建一并进行
