# spec-005：知识库构建与端到端验证闭环

对应基线：spec-001-中医AI问诊平台搭建.md、spec-002、spec-003、spec-004

## 变更原因

spec-002/003/004 的浏览器实测结论均建立在知识库产物之上，但当前 `storage/kb/` 为空，
`app.py` 会因 `load_knowledge_base()` 抛 `FileNotFoundError` 而 `st.stop`，
数据链路（问诊单 → 检索语句 → 混合检索 → 流式诊断）在当前环境无法复现。
本 spec 目标是补齐产物并闭环 spec-001「验证」章节，为后续优化提供可观测基线。

## 前置状态

| 项 | 状态 |
|------|------|
| 语料 | `data/medical_cases/` 6 个 MD，约 3.1 MB（最大《医学衷中参西录》1.7 MB） |
| 依赖 | 全局与 `.venv` 均 `pip check` 干净，32 例单测通过 |
| Key | `.env` 已配置 `DASHSCOPE_API_KEY`，已被 `.gitignore` 忽略 |
| 产物 | `storage/kb/`（faiss_index/、chunks.json、bm25.pkl）缺失 |

## 变更内容

| 文件 | 变更 |
|------|------|

（若实测暴露问题，另开 spec 记录修复，不在本 spec 内夹带）

## 执行步骤

1. 激活 `.venv`，执行 `python scripts/build_kb.py`，记录输出的块数统计与耗时
2. 核对 `storage/kb/` 产出三件产物：`faiss_index/index.faiss`、`chunks.json`、`bm25.pkl`
3. `streamlit run app.py` 启动，浏览器实测：
   - 步骤 1/3 生成检索语句（含原文展示）
   - 步骤 2/3 混合检索明细表（向量分 / 关键词分 / 融合分，核对 0.6/0.4 加权）
   - 步骤 3/3 流式诊断输出六小节（辨证分析 / 证型诊断 / 治法 / 推荐方药与加减 / 调护建议 / 引用医案依据）
   - 参考医案来源 [1]~[6] 带出处与相关度分数
4. 核对 spec-004 的 8 个问诊单分组标题全部渲染，字段齐全，中文无乱码
5. 记录一条真实样例问诊单的输入与输出，作为后续检索质量优化（spec-007）的对比基线

- 构建：`python scripts/build_kb.py` → `构建完成：共 3195 个知识块，产物已保存至 storage/kb/`，约 4 分钟
- 产物：`index.faiss` 12.5 MB、`index.pkl` 3.5 MB、`chunks.json` 3.6 MB、`bm25.pkl` 5.0 MB
- 检索语句：50 字，全中医术语（示例：不寐多梦易醒一月神疲乏力心悸头晕面色萎黄舌淡苔薄白脉细弱畏寒自汗纳呆口淡不渴思虑过度便溏尿清经少色淡）
- 混合检索：命中 6 条，最高融合分 0.600，两路明细符合 0.6/0.4 加权
- 流式诊断：2570 字，六小节齐全（辨证分析 / 证型诊断 / 治法 / 推荐方药与加减 / 调护建议 / 引用医案依据），148 秒
- 界面：`streamlit run app.py` HTTP 200，首页 7.2 KB 正常返回，无启动异常
- 单测：构建后重跑 32 passed

## 注意事项

- 构建会调用 DashScope 向量化接口（`text-embedding-v3`），产生少量费用与耗时
- 不将任何真实 Key 写入代码、测试、文档或提交内容
- 构建前脚本会清空 `storage/kb/`，属既定行为（健壮性问题见 spec-006）
